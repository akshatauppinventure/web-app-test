# ADR-0007: Frontend: Next.js 16 on Node.js 24 LTS

- **Status:** Accepted (2026-09-15)
- **Date:** 2026-09-14
- **Deciders:** Project owner
- **Related:** ADR-0011, ADR-0012, ADR-0019, ADR-0020

## Context

The owner requires React with Next.js. Next.js also acts as our **backend-for-frontend (BFF)**: it handles OIDC login server-side and calls FastAPI (ADR-0011).

Security history matters for this choice:
- **Dec 2025:** CVE-2025-66478 / CVE-2025-55182, "React2Shell": unauthenticated remote code execution in React Server Components, CVSS 10.0.
- **July 2026:** security release with 4 HIGH vulnerabilities.
- **August 2026:** two critical vulnerabilities, fixed in **16.3.3** / 15.5.24. One is RCE through the image optimizer when processing AVIF (a libheif/sharp bug); the other is Windows-only RCE.

Versions as of 2026-09-14:
- **Next.js 16.3.4** (2026-08-31, Active LTS).
- **Node.js 24** is Active LTS. Node.js 26 becomes LTS in October 2026.

## Decision

1. **Framework:** **Next.js 16.3.x** (App Router, TypeScript strict mode), with **React 19.2.x** at the patched version. **Hard minimum: `next >= 16.3.3`.** CI fails if the lockfile resolves lower.
2. **Runtime image:**
   - Multi-stage build on **`node:24-alpine`** (pinned by digest).
   - `output: 'standalone'`; the final stage copies only `.next/standalone`, `.next/static` and `public`.
   - Runs as the non-root `node` user with a read-only root filesystem (`tmpfs` for `.next/cache` if needed).
   - Upgrade to Node 26 LTS after October 2026 through a Renovate PR.
3. **Package manager: pnpm** (version pinned via the `packageManager` field), with a committed lockfile and `pnpm install --frozen-lockfile` in CI. Rationale: pnpm doesn't run dependency lifecycle scripts by default and supports release-age cooldowns. Both reduce npm supply-chain risk.
4. **Security-relevant settings:**
   - `images`: strict `remotePatterns` (none for the POC); `formats: ['image/webp']` (AVIF optimization stays off per the Aug 2026 advisory); `dangerouslyAllowSVG: false`.
   - `poweredByHeader: false`.
   - **Middleware/proxy is never used as the authorization boundary** (historic bypass CVE-2025-29927). Authorization is enforced server-side in route handlers and server components, and always again in FastAPI.
   - Security headers are set at Traefik (ADR-0012). Content Security Policy uses nonces generated by Next.js where inline scripts are required.
   - Server Actions: only for authenticated mutations. Next.js's built-in Origin checks are kept on; `serverActions.allowedOrigins` stays unset (same-origin only).
   - The browser never talks to FastAPI directly. Server-only modules are marked with `import 'server-only'`.
5. **Quality gates:** `eslint`, `tsc --noEmit`, `next build` and **Vitest** unit tests in CI. Playwright end-to-end tests come after the POC.

## Alternatives considered

| Option | Why not chosen |
|---|---|
| Next.js 15.5 (Maintenance LTS) | Older; 16.x is the active line |
| React SPA (Vite) + separate BFF | Loses server-side login/session handling in one app; owner requested Next.js |
| Remix / React Router 7, TanStack Start | Viable, but not requested; smaller ecosystems for our auth libraries |
| `node:24-slim` (Debian) runtime | Viable; alpine is smaller and is Next.js's documented example. Revisit if native module issues (sharp/musl) appear. |
| npm | Runs install scripts by default; fewer supply-chain guardrails |

## Consequences

**Positive**
- A mainstream stack with a large talent pool; login handled server-side keeps tokens out of the browser.

**Negative / risks**
- Next.js has a recent history of critical CVEs, so we **commit to a 48-hour patch SLA** (ADR-0020) and automated update PRs.
- `next-auth` v5 is published under a beta tag (see ADR-0011).

**Follow-ups**
- Upgrade to Node 26 LTS (Oct 2026). Add Playwright end-to-end tests before production.
